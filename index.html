01 Overview

SkillWins is an educational learning management platform designed to support student learning, training management, examinations, analytics, and secure payments. It brings user onboarding, course management, and subscription billing into one product, available on the web and as an Android app on Google Play. Its backend is a NestJS application running on AWS EC2.

02 The problem

A training organisation needs one place to deliver courses, run Campus Recruitment Training, conduct examinations, and collect course payments — while making sure each user only sees what their role permits, and every paid enrolment is backed by a verified payment.

03 Main features

  • Role-based accessAuthentication with role-based permissions across LMS modules.
  • Learning managementCourses, enrolments, and student progress tracking.
  • CRT managementCampus Recruitment Training programs managed in the platform.
  • Exams & analyticsExaminations with results and analytics.
  • Razorpay paymentsCheckout, payment verification, refunds, and subscription lifecycle.
  • WhatsApp notificationsAutomated course alerts and transactional messages.

04 My contribution & engineering responsibilities

  • Develop the platform's backend REST APIs with NestJS.
  • Deploy and run the NestJS backend on an AWS EC2 instance.
  • Built the platform's end-to-end flow: user onboarding, course management, and subscription billing.
  • Integrated the Razorpay payment gateway with webhook handling for payment verification, refund processing, and subscription lifecycle management.
  • Implemented the Meta WhatsApp Business API for automated user notifications, course alerts, and transactional messaging.
  • Designed Firestore data schemas and indexes for the platform's query patterns.
  • Enforced access control with Firebase Authentication — token-based sessions and role-based permissions.
  • Built the responsive Next.js and Tailwind CSS interface, with Cloudinary for media.

05 API & database design considerations

  • Model data around reads. Firestore is a document store, so schemas are shaped around how dashboards and course pages query data, with indexes for the frequent filtered queries.
  • Clear data domains. Users and roles, courses and content, enrolments and progress, exams and results, and payments are kept as separate concerns.
  • Server-owned writes for sensitive state. Enrolment and payment status change only after server-side verification, never directly from the client.
  • Predictable API behaviour. Validate input at the boundary and return consistent error responses the UI can handle.

06 Security & payment handling

  • Authenticated, role-checked access. Firebase Authentication tokens identify the user; role-based permissions decide what they can reach — enforced beyond the UI.
  • Verify, don't trust the browser. A successful checkout in the browser is not proof of payment; payments are verified on the server before access is granted.
  • Webhooks as the source of truth. Razorpay webhooks drive payment confirmation, refunds, and subscription changes, so state stays correct even if a user closes the tab mid-payment.
  • Secrets stay server-side. Gateway keys and API credentials live in the backend's server environment and are never shipped to the web or mobile client.

07 Challenges & solutions

Keeping payment and subscription state consistent

Client-side success callbacks can be missed or spoofed. Payment verification, refunds, and subscription lifecycle events are handled through Razorpay webhooks on the server.

Different users need different access

Firebase Authentication with role-based permissions governs which LMS modules each user can access, rather than relying on hidden UI elements.

Reaching learners at the right moment

The Meta WhatsApp Business API sends automated course alerts and transactional messages, so updates reach learners on a channel they already use.

Fast queries on a document database

Firestore schemas and indexes were designed around the platform's query patterns instead of mirroring a relational model.
